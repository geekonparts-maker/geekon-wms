# GeekOn WMS: σχέδιο (δικό μας WMS πάνω από το SoftOne)

> [AD] 16/11/2026. Ζωντανό έγγραφο: κάθε απόφαση του Άκη γράφεται εδώ.
> Το αρχικό σχέδιο PDA (Mantis LVS) μένει στη ρίζα του repo ως **πρότυπο εμφάνισης και ροών** (`GeekOn WMS.dc.html`, README).

## 1. Απόφαση
- Αγοράστηκε το Mantis LVS (εγκατάσταση `LV_GEEKON` στον server), αλλά η παραλαβή που φτιάξαμε στο PDA (repo `geekon-pda-wms`) δουλεύει άψογα.
  → Φτιάχνουμε **δικό μας WMS**, διαδικασία-διαδικασία, στα μέτρα μας.
- Το WMS είναι **ξεχωριστό λογισμικό με δική του βάση** στον server. Ό,τι αφορά την αποθήκη το κρατάει το WMS.
  Το **SoftOne** κάνει την τιμολόγηση / λογιστική και ενημερώνεται από το WMS μόνο σε εμπορικά γεγονότα.
- ΟΧΙ δεύτερη αποθήκη «WMS» μέσα στο SoftOne (διπλές μεταφορές, δύο αποθέματα να συμφωνούν, κόστος).

## 2. Υποδομή (επιβεβαιωμένη 16/11/2026)
- Windows Server 2019 Essentials, **SQL Server 2017 Express (RTM 14.0.1000)**, **Node v24.20.0**.
- Βάση SoftOne `GEEKON`: δεδομένα 2,8 GB (όριο Express 10 GB/βάση), log 13,3 GB αλλά 1% χρήση, SIMPLE (δεν το πειράζουμε τώρα).
- Βάση Mantis `LV_GEEKON`: 158 MB, SIMPLE.
- Σημείωση: RTM χωρίς Cumulative Update → κάποια στιγμή ο συνεργάτης να περάσει CU.

## 3. Αρχιτεκτονική
- **Βάση `GeekOnWMS`** (νέα, ίδιος SQL Server, SIMPLE, δικό της ημερήσιο backup). Δικός της SQL χρήστης που βλέπει **μόνο** αυτή.
  Το SoftOne μπορεί να **διαβάζει** από εκεί (π.χ. θέση είδους στην καρτέλα), ποτέ να γράφει.
- **Server WMS**: Node 24 (ίδια λογική με τον `pda-server.js`), οδηγός SQL `tedious`.
- **Διαχειριστικό** (web, από PC) + **εφαρμογή PDA** (η υπάρχουσα, μεταφέρεται).

### Σύνδεση με SoftOne
| Κατεύθυνση | Τι |
|---|---|
| SoftOne → WMS | είδη, barcodes, κωδικοί προμηθευτών (MTRSUPPRCS), αναμονές παραλαβής ΠΑΡ, παραγγελίες πελατών για picking |
| WMS → SoftOne | παραλαβή που ολοκληρώθηκε (ΠΣΚ/ΔΑ), picking που ολοκληρώθηκε (→ τιμολόγιο, υπάρχουσα ροή QR), διαφορές απογραφής (παραστατικό διόρθωσης, με έγκριση), έξοδος από την εταιρεία (επιστροφή σε προμηθευτή, καταστροφή) |

### Είδη (κωδικοί) από το SoftOne: αυτόματα (απόφαση Άκη 16/11)
- Το SoftOne είναι το **αφεντικό των ειδών**. Νέο είδος ανοίγει μόνο στο SoftOne. Το WMS **ποτέ** δεν γράφει είδη στο SoftOne.
- Ο server του WMS ρωτάει το SoftOne **κάθε 1-2 λεπτά** για είδη που άνοιξαν ή άλλαξαν (MTRL.INSDATE / UPDDATE) και ενημερώνει το WMS:
  κωδικός, περιγραφή, barcodes (CODE1/CODE2), κωδικοί προμηθευτών (MTRSUPPRCS), ενεργό/ανενεργό, φωτογραφία.
- Κάθε βράδυ **πλήρης σύγκριση** όλων των ειδών (πιάνει ό,τι δεν έχει ημερομηνία αλλαγής, π.χ. κωδικούς προμηθευτών).
- Είδος που απενεργοποιείται στο SoftOne → στο WMS γίνεται ανενεργό, **δεν σβήνεται** (μένει το ιστορικό του).
- Ανάγνωση: χρήστης SQL **μόνο για ανάγνωση** στη βάση GEEKON (ή μέσω των S1 Web Services όπως ο pda-server).

- Κάθε βράδυ **έλεγχος συμφωνίας**: σύνολο όλων των ζωνών WMS ανά είδος = απόθεμα SoftOne (αποθήκη 1000). Αναφορά διαφορών.

## 4. Ιχνηλασιμότητα: «να μη σβήνεται ποτέ τίποτα»
- Πίνακας κινήσεων **μόνο προσθήκη**: ώρα, χρήστης, συσκευή, είδος, ποσότητα, από θέση/ζώνη, σε θέση/ζώνη, παραστατικό, τι σκανάρισε, αιτία.
- **Triggers που απαγορεύουν UPDATE/DELETE** στη βάση. Λάθος = αντίθετη κίνηση (φαίνονται και οι δύο).
- Απόθεμα ανά θέση = άθροισμα κινήσεων → κατάσταση σε οποιαδήποτε στιγμή του παρελθόντος.
- Ιστορικό εισόδων χρηστών (κι αυτό δεν σβήνεται).

## 5. Χωροταξία
Ιεραρχία: **Όροφος → Διάδρομος → Dexion → Ράφι → Θέση** (+ ζώνες).

Κωδικός θέσης (όπως στο σχέδιο Mantis): **`IS-A02-D03-R01-P12`**
= Ισόγειο · Διάδρομος 02 · Dexion 03 · Ράφι 01 · Θέση 12. R01 = κάτω ράφι, P01 = αριστερή θέση από μπροστά.
Κάθε ράφι μπορεί να έχει διαφορετικό αριθμό θέσεων. Ετικέτες θέσεων: Code 128 + μεγάλος κωδικός (Zebra).

**Όροφοι (Άκης 16/11):**
| Κωδικός | Όροφος | Επίπεδο | Χρήση |
|---|---|---|---|
| IS | Ισόγειο | 0 | **fast picking** (ό,τι πουλάει πολύ) |
| YP | Υπόγειο | -1 | **slow picking** |
| O1 | 1ος όροφος | 1 | **ακίνητα / πολύ slow** |
(Ο κωδικός O1 είναι πρόταση, αλλάζει. Διαστάσεις: εκκρεμούν.)

→ **Τοποθέτηση βάσει ταχύτητας πώλησης (slotting):** η πρόταση θέσης στην τοποθέτηση λαμβάνει υπόψη τον ρυθμό πωλήσεων
(ήδη τον υπολογίζουμε στις προτάσεις παραγγελίας, CCCADFCSUM): γρήγορα → IS, αργά → YP, ακίνητα → O1.
Αναφορά **«προτεινόμενες μετακινήσεις»**: είδος που άρχισε να πουλάει και είναι στο YP/O1 → ανέβασέ το στο IS· είδος στο IS που δεν κινείται εδώ και Χ μέρες → κατέβασέ το.

**Παρτίδες: ΔΕΝ κρατάμε** (απόφαση Άκη 16/11). Η «Παρτίδα L-2265» του σχεδίου Mantis δεν υλοποιείται.

Όροφος: κωδικός 1-3 λατινικά (IS ισόγειο, YP υπόγειο, ...), επίπεδο (0, -1, 1), διαστάσεις.
Πρωτότυπο 3D διαχειριστικού: `admin/3d-apothiki.html` (three.js r128, αποθήκευση προς το παρόν στον browser).

## 6. Ζώνες / εσωτερικές αποθήκες WMS (ζήτηση Άκη 16/11)
Μετακίνηση ανάμεσα σε ζώνες = μόνο στο WMS, **καμία ενημέρωση ποσότητας στο SoftOne**.
| Ζώνη | Μετράει στο SoftOne | Πουλιέται |
|---|---|---|
| Κύρια (ράφια) | ναι | ναι |
| Παραλαβή / προς τοποθέτηση | ναι | όχι ακόμα |
| Faulty | ναι (μέχρι απόφαση) | όχι |
| Service / έλεγχος | ναι | όχι |
| Επιστροφές πελατών | ναι | όχι |
| Προς επιστροφή σε προμηθευτή | ναι (μέχρι να φύγει) | όχι |

**Ανοιχτό:** αφού η ποσότητα SoftOne δεν αλλάζει, το eshop βλέπει τα μη διαθέσιμα σαν διαθέσιμα. Επιλογές:
(1) δεν μας πειράζει, (2) πεδίο «Μη διαθέσιμα» στο είδος του SoftOne και eshop = απόθεμα − μη διαθέσιμα (αν το επιτρέπει το Softify),
(3) δέσμευση στο SoftOne.

## 7. Χρήστες / είσοδος (όπως το Mantis)
Εγκατάσταση/εταιρεία (GeekOn) · Επιχειρησιακή μονάδα/αποθήκη · Όνομα χρήστη · Κωδικός (hash) · Γλώσσα.
Ρόλοι: Διαχειριστής, Υπεύθυνος αποθήκης, Picker (μόνο PDA), Προβολή. Διαχειριστής + Authenticator (όπως η Αναφορά GeekOn).
PDA: PIN όπως τώρα, χρήστες από το διαχειριστικό.

## 8. Φάσεις (ενότητες PDA όπως το σχέδιο: RCV, PUT, PICK, PACK, RPL, INV, MOV, FND, LBL)
0. ✅ **Παραλαβή** (live στο `geekon-pda-wms`) · ✅ **Ετικέτες** (scan → τυπώνει, κωδ. προμηθευτή → δικό μας SKU)
1. Διαχειριστικό: είσοδος, χρήστες, **3D αποθήκη** (όροφοι/Dexion/θέσεις), ετικέτες θέσεων. Βάση `GeekOnWMS`.
2. Αρχική απογραφή ανά θέση (ξεκίνημα με σωστό απόθεμα).
3. **Τοποθέτηση** μετά την παραλαβή (scan είδους → scan θέσης, πρόταση + override).
4. **Μετακινήσεις / Αναπλήρωση**.
5. **Picking** (directed, auto-advance) → SoftOne τιμολόγιο.
6. **Packing**.
7. **Απογραφή** κυκλική (τυφλή) → διαφορές με έγκριση → SoftOne.
8. **Ζώνες** (faulty/service/επιστροφές).
9. Αναφορές: απόθεμα ανά θέση, ασυμφωνίες, παραγωγικότητα, αργοκίνητα ανά ράφι.
